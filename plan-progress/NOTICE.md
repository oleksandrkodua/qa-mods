Fork of `plan-progress` 0.7.6 from github.com/zycck/claude-mods (MIT, author: Kirill Serditov; upstream commit ace3350, 2026-10-06). The upstream licence is in `LICENSE.upstream`.
The plugin name stays `plan-progress`, so the tool is still `mcp__plan-progress__plan_progress` and the skill `plan-progress:plan-progress`. Install this INSTEAD of `plan-progress@zycck-mods`, never next to it (two copies would draw two bars and register the same tool).
Changes in `hooks/register.tsx` (desktop drawing only; the terminal path is untouched):
1. (0.7.6-qa.1) The title width estimate used 6.4 px per character, too narrow for Cyrillic (~9.6 px), so titles were cut after a few letters while the track kept over a thousand px. Cyrillic letters now count 9.2 px (`textWidth`), Latin keeps 6.7, and a title may take up to 40% of the band (was 30%).
2. (0.7.6-qa.1) Hovering the title shows a card with the full title and the same status text the alt text carries (stage, step, percent, note). A keyed `Box` is the hover scope; the card is an absolute `Box` with `display: none` that hover turns to `flex`.
3. (0.7.6-qa.2) The interface is Ukrainian: the footer button (`Прогрес`, `Прогрес 2`), the first-start toast, the descriptions and answers of `/progress` and `/progress-clear`, the agents bar (`Агенти`, `N працює`, `ще N агентів · M готово` with Ukrainian plural forms), the hover text of a bar (`готово, 3 кроки за 2х 20с`, `крок 1 з 2`), default titles (`План`, `Крок`, `Завдання`) and the clock units: `с`, `х`, `г` instead of `s`, `m`, `h` (one letter each, so the clock keeps its width). **Not translated on purpose:** `RULES` and the hook messages that are addressed to the model (denials, "still open", tool description and its parameters), the skill text, and the agent state words (`running`, `done`) in a hover text of a strip. `tests/regress.mjs` expects the Ukrainian units.
4. (0.7.6-qa.3) The footer row of the `Progress` button has `flexShrink={0}`, so the host does not squeeze it into `…` next to the Compact and Clear buttons (attempt; not yet seen live).
5. (0.7.6-qa.4) The Windows PowerShell sound fallback is removed (`play()` is one `$.audio.play` call). The `sounds/*.wav` stay: the engine's player (afplay on macOS) uses them.
6. (0.7.6-qa.5) The footer `Progress` button (the `SessionMode` hook) is removed; the hud band has a `Прогрес` button that runs `/progress` (the toggle and its texts are unchanged; pressed from a plugin it answers with a toast, not a transcript line). `tests/regress.mjs` expects no footer buttons.
To take a newer upstream version: diff upstream `plugins/plan-progress/hooks/register.tsx` against this one and re-apply the six changes by hand.
Tests: the upstream `tests/regress.mjs` still passes; `tests/qa-fork.mjs` is ours (hover card, title room). Compile `register.tsx` to `tests/register.mjs` as `tests/README.md` says; without a global TypeScript use Bun: `new Bun.Transpiler({ loader: 'tsx', tsconfig: JSON.stringify({ compilerOptions: { jsx: 'react', jsxFactory: 'h' } }) })`, then replace `from 'claude-code'` with `from './stub.mjs'`.
7. (0.7.6-qa.10) The title cell has a fixed width and cuts a long title with `…` (it used to push the track off the right edge); a title that does not fit gets a `▾` button that opens it in full, wrapped (`▴` closes it).
8. (0.7.6-qa.10) `MAX_BARS` is 5 (upstream 3): a 4th bar no longer pushes the oldest one out. `tests/regress.mjs` expects the new limit.
9. (0.7.6-qa.10) The hover card appears only for a cut title and shows the title alone; the title cell width is in columns, not px.
10. (0.7.6-qa.10) A title is kept up to 160 characters and, when longer, cut at a word with an ellipsis (upstream: 80, mid-word, no ellipsis); a hairline is drawn above the first bar as well, so the band row above does not touch it.
11. (0.7.6-qa.10) With 4 or more bars the finished ones fold into one line `✓ N готово ▾` (opens them; `✕` drops them); the Stop-hook reminder says that a bar the user asked to keep open, or that waits on the user, is set to `needs_input` with a note and is not closed; `expanded` and `doneOpen` are declared in the state contract.
10. (0.7.6-qa.11) `NARROW` is 260 (was 360): the pill keeps the stage name on an ordinary panel and turns into a number only on a really narrow one.
11. (0.7.6-qa.11) Finished bars are kept until closed with `✕` and no longer count against `MAX_BARS` (the 6th open bar used to push a green one out); only the `MAX_DONE` = 8 newest finished bars are remembered.
12. (0.7.6-qa.11) A step takes an optional `detail` (one short line). Every bar has a `▾` that opens its steps (`○ ● ✓ ✕ –`, the detail after a dash) and a footer with the stage, the time and the note; `▴` closes it. The `▾` used to appear only for a cut title.
13. (0.7.6-qa.12) `MAX_BARS` is 20 and only a runaway guard: running bars are no longer pushed out by the 6th and 7th (a later `done`/`next` on a pushed-out bar failed with "no bar"). `regress.mjs`: `running_bars_are_not_pushed_out_below_the_guard`.
14. (0.7.6-qa.13/14, from other chats) see INSTALL.md decisions log.
15. (0.7.6-qa.15) The fold line `✓ N готово ▾` (a bar finished 60 s ago, DONE_HOLD_MS) drew its hairline in the same row as the text, so the text was pushed off the edge and only an empty band with a line was left; the hairline is now above the row.
