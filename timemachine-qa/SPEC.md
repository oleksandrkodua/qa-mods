# SPEC: timemachine-qa (форк сесії: код + розмова)

Статус: спек, код не написаний. Дата: 2026-10-06. Контекст рішень: `CONTEXT.md` п. 13, `HANDOFF.md` «Открыто» п. 1.

## Навіщо
Сторонній `session-time-machine` (`/timemachine`) форкає лише розмову, код лишається як є, а на робочих сесіях (20–42 МіБ) падає з `file is over the 4194304-byte limit` (мод читає файл цілком через `$.fs.read`). Потрібно: повернутися до точки X і мати **і розмову, і код** такими, якими вони були в X, не чіпаючи поточну сесію.

## Не цілі
- Не відкочує поточну сесію (API мода не вміє): результат завжди нова сесія + нова робоча тека.
- Не міняє гілки/індекс/робоче дерево користувача, нічого не комітить і не пушить.
- Не читає файл розмови в пам'ять мода.

## Точки форку
Точка = рядок розмови, після якого ріжемо: `prompt` (форк ДО цього промпта), `tool call` (включно з результатом), `turn end`. Список точок будується без читання всього файлу (див. «Індекс»).

## Знімок коду (на кожен turn)
На `turn.complete` (і `turn.start` для першого ходу) мод фіксує знімок, не торкаючись індексу користувача:
1. `GIT_INDEX_FILE=<tmp>` — тимчасовий індекс, ініціалізований з `HEAD` (`git read-tree HEAD`).
2. `git add -A -- :/` у цей тимчасовий індекс, **з виключеннями** (див. «Секрети»); потім `git write-tree` → `git commit-tree <tree> -p <попередній знімок|HEAD> -m "tmqa <sessionId> <uuid рядка>"`.
3. Ref: `refs/tmqa/<sessionId>/<n>` (не гілка, не потрапляє в `git branch`, `git push` його не бере).
4. Відповідність «uuid рядка розмови → commit» зберігається в `~/.claude/timemachine-qa/<sessionId>.json` (малий індекс, мод створює сам; пише мод, не Bash-пісочниця).
Знімок робиться лише якщо дерево змінилося щодо попереднього знімка (порівняння tree-hash), щоб не плодити порожні.

### Секрети (критично)
`~` — git-репозиторій із секретами (`.babtsya-secret`, ключі). Тому:
- Знімок вмикається лише для тек, де користувач явно ввімкнув (`/tmqa on` у корені проєкту) або де є `.tmqa`; для `~` — **відмова за замовчуванням** з поясненням.
- `add` лише через allowlist/denylist: за замовчуванням береться `git ls-files -m -o --exclude-standard` (це враховує `.gitignore`), далі викидаються шаблони `*secret*`, `.env*`, `*.pem`, `*.key`, `id_*`, `.babtsya-*`, а також файли > `maxFileMiB` (за замовчуванням 5).
- Перед `write-tree` показується підсумок «N файлів, виключено M» (у VS Code — в тексті, в десктопі — в панелі).
- Знімки живуть локально; нічого не віддається назовні, `refs/tmqa/*` явно виключені з `push` (мод ніколи не викликає push).

## Форк (дії при виборі точки N)
1. **Код:** `git worktree add <ws>/tmqa-<id> <commit для точки N>` (detached). Якщо для N знімка немає (знімок = найближчий попередній за часом) — показати, який взято, не вгадувати мовчки. Неочищені зміни користувача не зачіпаються (worktree окрема тека).
2. **Розмова (без читання у мод):** shell-конвеєр у `$.process.run`:
   `head -n <CUT> <src.jsonl> | grep -v '"type":"bridge-session"' | sed 's/<OLD>/<NEW>/g' > <projDirДляWorktree>/<NEW>.jsonl`
   - `CUT` = номер останнього рядка типу `user`/`assistant` не пізніше точки N (рядок `queue-operation` перед наступним промптом несе його текст — не включати).
   - `NEW` = новий UUID; `OLD` = id вихідної сесії; `bridge-session` вирізаємо, інакше в копії попередження Remote Control.
   - Файл кладеться в теку проєкту **worktree** (`~/.claude/projects/<закодований шлях worktree>/`), бо `claude --resume` шукає за cwd. Саме мод пише туди (пісочниця Bash не може; мод працює в хості — перевірити на першій реалізації, інакше дати користувачу команду для Terminal).
3. **Вихід:** команда `cd '<worktree>' && claude --resume <NEW> ['<інструкція>']` скопійована в буфер + показана.
4. Вихідна сесія й робоча тека не змінюються.

`CUT` обчислюється **потоково** (одним проходом `python3`/`awk` по файлу через `$.process.run`, вивід = номер рядка і метадані точки), а не `$.fs.read`; обмеження 4 МіБ обходиться тим, що файл ніколи не потрапляє в мод.

## Індекс точок
`awk`/`python3`-прохід по jsonl збирає: номер рядка, `type`, uuid, час, перші 60 символів промпта (з вичищенням `<ide_opened_file>`/`<ide_selection>`/`<system-reminder>`, службових `<command-name>`/`<local-command`), ім'я інструмента. Кеш у `~/.claude/timemachine-qa/<sessionId>.idx.json`, донабір з останнього відомого офсету (append-only файл), повний перепрохід лише якщо розмір менший за збережений.

## Інтерфейс
- **Десктоп (Code):** права панель: таймлайн точок (як у `session-time-machine`) + позначка «є знімок коду». Вибір точки → кнопка «Форк тут» → діалог `$.ui.ask` (Confirm / Cancel) з підсумком: точка, кількість рядків, взятий знімок, виключені файли.
- **VS Code:** панелей немає: `/tmqa list`, `/tmqa fork <n> [інструкція]`, підтвердження діалогом.
- **CLI:** те саме, що VS Code (текст + діалог).
- Підписи українською (за правилом `CONTEXT.md`), INSTALL.md англійською.

## Обмеження та відомі ризики
1. Знімок не включає те, що поза git-деревом (БД, `node_modules` під `.gitignore`, мережеві ефекти). Повернення розмови ≠ повернення світу: у виводі явно писати.
2. Форк на точці всередині tool-виклику: модель у копії бачить результат, але зовнішні ефекти (запис у чужий сервіс) не відкочуються.
3. `bridge-session` вирізаємо; чи є ще рядки, що викликають побічні ефекти при resume (`atis-latch`, `cost-state`) — **не перевірено**, прибрати лише якщо тест покаже проблему.
4. Рядки `file-history-snapshot`/`file-history-delta` у копії посилаються на messageId до точки — dangling не знайдено (див. тест 3), але повернення файлів через `/rewind` у копії не перевірялося.
5. Великі сесії: час `head|grep|sed` ≈ 0.8 с (21 МіБ), 1.0 с (28 МіБ), 1.6 с (41 МіБ) на цій машині.
